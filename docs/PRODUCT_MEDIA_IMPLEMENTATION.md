# وحدة إدارة صور الأصناف — TOOFAN SOFT

**الإصدار:** 1.0  
**حالة التنفيذ:** ضمن Pull Request رقم 5 — مراجعة CI مطلوبة  
**النطاق:** شاشة المخزون، Dexie/IndexedDB، SQLite/Electron، Supabase Storage

## 1. القرار الوظيفي

- لكل صنف صورة رئيسية واحدة.
- يسمح بما يصل إلى خمس صور إضافية؛ الحد الإجمالي ست صور للصنف.
- أول صورة تضاف تصبح الرئيسية تلقائياً.
- يمكن تغيير الصورة الرئيسية وحذف الصور.
- عند حذف الصورة الرئيسية، تترقى أول صورة متبقية تلقائياً.
- عرض الصور متاح لمستخدم المخزون المصرح له، بينما الإضافة والتغيير والحذف تحتاج inventory:media:manage.
- لا يسمح بحذف الصنف حتى تؤكد المزامنة حذف كل صوره؛ هذا يمنع حذف سجل الأب بينما ما زالت مراجع صور معلقة في Outbox أو لدى الأجهزة الأخرى.

## 2. الفصل بين الصورة وبيانات الصنف

لا يضاف حقل Base64 أو ملف الصورة إلى Product، ولا تنسخ الصور إلى الفواتير أو القيود. تحفظ بيانات وصفية مستقلة في:

- Dexie: جدول productImages ضمن schema v7.
- SQLite: جدول product_images ضمن migration 003_product_images.sql.
- Supabase: جدول erp_product_images.

تتضمن metadata معرّف الصورة والمؤسسة والنشاط والصنف ومفاتيح التخزين والنوع والحجم والأبعاد وبصمة SHA-256 وتحديد الصورة الرئيسية والترتيب والموظف والحالة.

## 3. أماكن التخزين

### الويب / PWA
تحفظ ملفات WebP الأصلية والمصغرة كـ Blob في IndexedDB داخل productImages. لا يتطلب عرضها اتصالاً بعد تخزينها محلياً.

### Windows / Electron
تحفظ الملفات خارج ملف EXE وقاعدة SQLite، داخل مجلد بيانات التطبيق المستقر:

%APPDATA%\AmroAlnmaryERP\ProductMedia

مفاتيح الملفات تتبع النمط:

tenant/activity/product/image/original.webp  
tenant/activity/product/image/thumbnail.webp

### التخزين السحابي
يستخدم Supabase Storage bucket خاصاً باسم erp-product-media. لا تنشأ روابط عامة للصور؛ يجري الرفع والتنزيل عبر JWT المستخدم وسياسات Storage RLS.

## 4. معالجة الصورة والتحقق

- واجهة المستخدم تقبل JPG وPNG وWebP من الكاميرا أو المعرض.
- يضغط المتصفح الصورة إلى WebP، بحد أقصى 1600px للضلع الأطول، وينشئ thumbnail بحد 360px.
- حد حجم الملف الأصلي قبل الضغط 10MB.
- حد الملف المحفوظ 10MB، وحد thumbnail 1MB، والأبعاد المسجلة لا تتجاوز 4096×4096.
- التحقق من MIME signature الحقيقي، وليس اسم الملف أو MIME المرسل فقط.
- رسم الصورة على Canvas قبل الحفظ يزيل بيانات EXIF الأصلية، بما فيها بيانات الموقع الجغرافي.
- يحسب SHA-256 للأصل، ويعاد التحقق من الحجم والبصمة عند تنزيل الملف من Supabase.
- التخزين المكتبي يرفض مسارات الملفات غير المسموحة ومحاولات الخروج من مجلد ProductMedia.

## 5. المزامنة والعمل دون اتصال

1. تحفظ metadata وBlob محلياً مع Outbox مستقل من نوع PRODUCT_IMAGE.
2. تعتمد عملية رفع الصورة على وجود الصنف أولاً.
3. في Supabase، يرفع النظام الأصل وthumbnail إلى الـ private bucket، ثم يزامن metadata.
4. عند تنزيل صورة إلى جهاز آخر، يتحقق النظام من المؤسسة والنشاط والصنف والحجم وبصمة SHA-256 قبل تخزينها محلياً.
5. حذف الصورة يرسل tombstone إلى جدول metadata، ثم يحذف الكائنين من Storage. بعد تأكيد الخادم فقط تزال tombstone المحلية.
6. إذا كان الجهاز بلا إنترنت، تبقى الصورة والحذف في التخزين المحلي وOutbox حتى عودة الاتصال.
7. يعالج سحب صور الأصناف قبل إزالة الأصناف محلياً، حتى تزال صور الصنف على الأجهزة الأخرى قبل تطبيق حذف الصنف.

## 6. الصلاحيات

| الدور | عرض الصور | إضافة / تغيير الرئيسية / حذف |
|---|---:|---:|
| ADMIN | نعم | نعم |
| ACCOUNTANT | نعم | نعم |
| INVENTORY_KEEPER | نعم | نعم |
| CASHIER | نعم | لا |

تطبق الخدمات المحلية فحص المؤسسة والنشاط قبل القراءة والتعديل. تفرض سياسات Supabase عزل المؤسسة والدور، وتتحقق من ارتباط مسار ملف Storage بالصنف والنشاط المسجلين.

## 7. النسخ الاحتياطي والاستعادة

- نسخ SQLite الاحتياطية المكتبية تنشئ ملف قاعدة البيانات، ومجلد sidecar مجاوراً باسم اسم-النسخة.sqlite.media.
- مجلد sidecar يحتوي ملفات ProductMedia اللازمة لاستعادة الصور.
- عند استعادة نسخة قديمة لا تتضمن سجلات صور، ينظف مجلد الصور المحلي.
- إذا تضمنت قاعدة البيانات سجلات صور ولم يوجد sidecar، يرفض النظام الاستعادة ويرجع قاعدة البيانات ومجلد الصور إلى نسخة الأمان السابقة.
- يجب نقل ملف .sqlite ومجلد .sqlite.media معاً للحفاظ على الصور.
- تصدير JSON القديم لا يعد نسخة كاملة لملفات الصور الثنائية؛ استخدم النسخ الاحتياطي الأصلي SQLite مع sidecar عند الحاجة إلى نسخة كاملة من صور الأصناف.

## 8. التكامل السحابي ومتطلبات التفعيل

قبل استخدام مزامنة الصور في Supabase، شغّل SQL المحدث من:

- src/db/supabaseRlsPolicies.sql
- الملف TypeScript src/db/supabaseRlsPolicies.ts هو المرآة البرمجية المطابقة للـ SQL.

ينشئ SQL جدول erp_product_images، والـ private bucket، وسياسات RLS اللازمة.

**Django:** موصل Django الموجود حالياً لا يوفر endpoint لرفع/تنزيل ملفات الصور الثنائية. لذلك يضع النظام عناصر صور Django في حالة فشل واضحة ولا يدعي نجاح المزامنة. يلزم تطوير endpoint تخزين آمن في خادم Django قبل تفعيل مزامنة الصور من خلاله.

## 9. حدود التأثير

عمليات الصور لا تستدعي saveProductAtomic ولا adjustProductStockAtomic، ولا تغير أسعار الصنف أو كمياته أو التشغيلات أو الفواتير أو الأرصدة أو القيود أو الأرباح.

## 10. بوابة القبول قبل الدمج

- نجاح npm run lint.
- نجاح npm run verify:architecture.
- نجاح npm test.
- نجاح npm run test:sqlite بما فيه scripts/tests/product_media.test.mjs.
- نجاح npm run test:legacy.
- نجاح npm run build.
- نجاح sqlite-electron-runtime وwindows-exe-preview في GitHub Actions.
- فحص يدوي على Windows وPWA بعد تنزيل artifact: إضافة صورة، فصل الإنترنت، عرضها دون اتصال، عودة الشبكة، التحقق من ظهورها على جهاز آخر، حذف الرئيسية، النسخ والاستعادة.

لا يعتبر نجاح CI بديلاً عن اختبار الكاميرا الفعلية أو اختبار أجهزة متعددة أو التحقق من مشروع Supabase الفعلي.
