# بروتوكول الاستمرارية بين المحادثات والأدوات

## الهدف والنطاق
هذا البروتوكول إلزامي لكل من يعمل على هذا المستودع: ChatGPT، Claude، Gemini، Copilot، Cursor، Codex، المطور البشري، وأي أداة أخرى. لا تعتمد الأداة على ذاكرة محادثة سابقة بوصفها مصدر الحقيقة. GitHub هو سجل المشروع المشترك.

## أمر العمل النشط
- افحص `docs/ai/ACTIVE_WORK_ORDER.md` في الفرع الحالي أو فرع PR المرتبط بالمهمة.
- إذا كانت الحالة `APPROVED — READY TO EXECUTE`، اقرأ الوثيقة التنفيذية المشار إليها بالكامل؛ هذه موافقة مالك محددة وليست مجرد اقتراح.
- لا تطلب من المالك إعادة الموافقة على النطاق المكتوب صراحة، ولا تتجاوز حدوده. الدمج وأي توسع يظلان بحاجة إلى موافقة مستقلة.
- قبل كتابة الكود أعد التحقق من أحدث `main` وPRs والفروع وCI، ثم تابع على فرع مستقل دون استبدال عمل أي أداة أخرى.
- إذا كانت الحالة `IN_PROGRESS`، استأنف من آخر تحديث موثق وSHA؛ لا تبدأ تنفيذًا موازيًا.
- لا تعتبر إنشاء أمر العمل أو قراءته دليلًا على أن كوده قد نُفذ.

## عند بدء أي جلسة
1. حدّد المستودع والفرع وHEAD الحالي واطلب مراجعة حالة PRs المفتوحة قبل التعديل.
2. اقرأ `AGENTS.md` كاملًا.
3. اقرأ `docs/ai/00-project-overview.md` و`docs/ai/05-decisions-and-open-gates.md` و`docs/ai/07-decision-log.md`.
4. اقرأ `docs/ai/06-cross-tool-continuity.md` وهذا البروتوكول.
5. اقرأ الوثائق التخصصية ودفتر التقدم المرتبط بالمهمة. لمبادرة المنتجات، اقرأ SPEC وDESIGN وPLAN وPROGRESS كاملة.
6. قارن آخر SHA في دفتر التقدم مع HEAD الحالي. إذا اختلفا، افحص commits والملفات المتغيرة قبل الاستكمال.
7. تحقق من حالات GitHub Actions للـ HEAD الحالي، ولا تستخدم حالة قديمة على أنها الحالة الحالية.
8. اكتب ملخص استلام قصيرًا: ما اكتمل بالدليل، ما لم يبدأ، ما ينتظر المالك، والخطوة التالية المسموحة.

## أثناء العمل
- افصل بين: قرار معتمد، توصية، سؤال مفتوح، تنفيذ فعلي، واختبار ناجح.
- لا تحول الموافقة العامة إلى موافقة على تفاصيل تقنية أو محاسبية غير مذكورة.
- كل موافقة تسجل في سجل القرارات مع النص المعتمد، النطاق، التاريخ، المرجع، وما لا تغطيه.
- إذا كان القرار مؤثرًا في التصميم أو التنفيذ، لا تبدأ الجزء المحجوب حتى توثيق الموافقة.
- إذا لم تتوفر أداة GitHub أو تعذر التحقق من الحالة، توقف قبل الكتابة واطلب تمكين الاتصال؛ لا تخمّن.
- لا تستبدل عملًا غير مفهوم أو تغييرات أداة أخرى. افحص وسجّل التعارض أولًا.

## قبل التوقف أو تسليم العمل
1. ارفع العمل إلى فرع المهمة، لا إلى `main` مباشرة.
2. حدّث دفتر التقدم المختص: المهمة، الحالة، الملفات، الاختبارات، HEAD SHA، PR، والقرار/الخطوة التالية.
3. حدّث سجل القرارات فقط إذا صدر قرار أو موافقة جديدة؛ لا تسجل التوصيات كموافقات.
4. اذكر ما لم يتغير، خصوصًا قاعدة البيانات والمحاسبة والبيانات والصلاحيات.
5. اذكر الاختبارات التي شُغلت فعليًا وبيئتها ونتيجتها؛ لا تساوِ CI باختبار ميداني.
6. اترك PR مفتوحًا. الدمج أو الإغلاق أو تغيير الوجهة يحتاج موافقة مستقلة صريحة.

## قاعدة التعارض
إذا اختلفت المحادثة عن GitHub، استخدم أحدث سجل موثق على GitHub. إذا اختلف دفتر التقدم عن حالة GitHub أو كان SHA قديمًا، افحص الواقع الحالي ثم حدّث الدفتر. لا تخترع موافقة أو تاريخًا أو نتيجة اختبار.
