# خطة تحويل نظام الإدارة إلى Windows EXE + SQLite

تاريخ البدء: 2026-11-20  
الفرع: feature/windows-exe-sqlite  
النسخة الأساسية: 910bf97507cd5e0c5a64300873e9883ca9cafbb3

## الهدف المعتمد

تسليم برنامج Windows مستقل قابل للتثبيت والتشغيل دون الحاجة إلى متصفح أو Node.js مثبت لدى المستخدم، مع قاعدة SQLite محلية فعلية تحفظ جميع البيانات بعد إغلاق البرنامج أو إعادة تشغيل/إطفاء الجهاز، وتبقى سليمة بعد تحديث البرنامج.

## شروط العمل التجاري المعتمدة

1. **الحفظ الدائم:** كل عملية مالية أو تشغيلية ناجحة تُحفظ في ملف SQLite المحلي، ولا تعتمد النسخة النهائية على ذاكرة مؤقتة أو localStorage أو IndexedDB كمصدر أساسي للحقيقة.
2. **استمرار البيانات بعد الإغلاق:** إغلاق النافذة أو البرنامج أو Windows لا يمسح قاعدة البيانات. عند إعادة التشغيل تُفتح نفس القاعدة ويستعيد النظام آخر العمليات التي تم اعتمادها بنجاح.
3. **سلامة العمليات:** تستخدم العمليات المالية معاملات SQLite ذرية؛ إما أن تُحفظ العملية كاملة، أو يتم التراجع عنها كاملة عند فشلها. لا تظهر عملية جزئية أو رصيد غير متوازن بسبب توقف التطبيق أثناء المعاملة.
4. **التحديث دون فقد البيانات:** تحديث EXE أو تثبيت إصدار أحدث فوق السابق لا يحذف قاعدة البيانات ولا يستبدلها بقاعدة فارغة. تبقى قاعدة البيانات في مسار بيانات مستخدم ثابت ومستقل عن مجلد تثبيت البرنامج.
5. **ترحيل مخطط القاعدة:** كل تحديث يحتاج تغييرًا في الجداول يمر عبر migrations مرقمة، مع نسخة احتياطية مُتحقق منها قبل تنفيذ ترحيل قاعدة البيانات. لا يبدأ التشغيل التشغيلي إذا فشل الترحيل أو فحص سلامة القاعدة.
6. **إلغاء التثبيت:** لا يحذف برنامج إلغاء التثبيت بيانات المستخدم تلقائيًا. حذف البيانات يكون إجراءً منفصلًا وصريحًا مع تحذير واضح وخيار أخذ نسخة احتياطية.
7. **النسخ الاحتياطي:** توجد نسخة احتياطية يدوية، ونسخ تلقائية دورية قابلة للضبط، ونسخة قبل ترقية إصدار البرنامج أو مخطط القاعدة. يمكن تصدير النسخة إلى قرص أو مسار خارجي.
8. **الاستعادة:** تُفحص النسخة الاحتياطية قبل الاستعادة، وتتم الاستعادة إلى ملف مؤقت ثم التحقق منه قبل استبدال قاعدة التشغيل. لا تستبدل قاعدة سليمة بملف تالف.
9. **العمل دون إنترنت:** تستمر العمليات المحلية المسموح بها دون إنترنت؛ الاتصال ليس شرطًا لحفظ البيانات محليًا. المزامنة المستقبلية لا تستبدل السجل المحلي بصمت.
10. **حدود الحماية:** حفظ البيانات على نفس القرص لا يحمي من تلف القرص أو فقدان الجهاز؛ لذلك يجب أن يستطيع المستخدم إخراج نسخة احتياطية إلى وسيط آخر.

## القرار التقني

- Electron لتغليف واجهة React الحالية في برنامج Windows مستقل.
- SQLite عبر better-sqlite3 داخل عملية Electron الرئيسية فقط.
- واجهة React تتصل بقاعدة البيانات عبر IPC محدود ومتحقق منه من خلال preload.
- contextIsolation=true وnodeIntegration=false وsandbox=true.
- منع وصول الواجهة إلى filesystem أو SQL أو Node.js مباشرة.
- استخدام app.getPath('userData') مع اسم تطبيق ثابت ومسار قاعدة ثابت، مثل مجلد data داخل userData؛ لا يوضع ملف البيانات بجوار EXE أو داخل مجلد التثبيت.
- تفعيل WAL وforeign_keys وbusy_timeout وsynchronous=FULL، واستخدام معاملات SQLite للعمليات المالية المركبة.
- تنفيذ فحص سلامة القاعدة عند بدء التشغيل، ومعالجة سجل WAL وفق آليات SQLite، وعدم نسخ ملف القاعدة الحي بنسخ ملفات عادية قد تتجاهل WAL.
- استخدام SQLite online backup API أو آلية إيقاف/إغلاق/checkpoint موثوقة لإنتاج نسخ كاملة متسقة.
- لا يتم اعتبار IndexedDB مصدرًا دائمًا للحقيقة في نسخة Windows النهائية.

## الوضع الحالي المثبت

المستودع الحالي React/Vite وDexie/IndexedDB. طبقة Dexie مستخدمة مباشرة في db/erpDatabase.ts وservices/dexieDataService.ts وhooks/useLiveDexie.ts وفي مكونات متعددة. لذلك لا يكفي إضافة Electron وملف SQLite فارغ؛ يجب نقل عمليات القراءة والكتابة والمعاملات والاشتراكات إلى موفر بيانات SQLite فعلي.

## مراحل التنفيذ الإلزامية

### WEX-01: تأسيس سطح Windows الآمن
- إضافة Electron main/preload.
- نافذة محلية تحمل ملفات dist فقط.
- تعطيل التنقل الخارجي وفتح الروابط الخارجية عبر النظام بعد التحقق.
- إعداد أيقونة التطبيق واسم المنتج وإعدادات البناء.
- تعطيل IPC العام أو تنفيذ SQL قادم من renderer.

### SQL-01: محرك SQLite ومخطط البيانات
- إضافة better-sqlite3 داخل main فقط.
- مخطط إصدار أول مع migrations متسلسلة.
- جداول المؤسسة والفروع والمستخدمين والأنشطة والحسابات والأصناف والتشغيلات والأطراف والفواتير والقيود والصناديق والسندات والأمانات وسجل التدقيق وطابور المزامنة والتسلسلات.
- مفاتيح أساسية وخارجية وفهارس وقيود تحقق.
- اختبار المعاملات الذرية، وإغلاق القاعدة وإعادة فتحها، واستعادة WAL، وفحص integrity_check.
- عدم اعتماد قاعدة فارغة أو seed يعيد ضبط بيانات موجودة.

### DATA-01: نقل طبقة البيانات
- بناء واجهة موحدة لموفر البيانات مع تنفيذ SQLite.
- نقل العمليات المالية الذرية إلى معاملات SQLite.
- نقل الاشتراكات الحية في الواجهة إلى آلية إشعار آمنة بعد نجاح الكتابة.
- ترحيل Dexie الحالي إلى SQLite دون حذف أو تعديل المصدر القديم.
- مقارنة أعداد السجلات والمجاميع المالية والأرصدة قبل وبعد النقل.
- عدم إكمال التحويل بكتابة طبقة توافق شكلية تخفي استمرار الاعتماد على Dexie.

### SEC-01: حماية التطبيق والبيانات
- فرض صلاحيات المستخدم والفرع والمؤسسة في main/data layer، لا في React وحدها.
- التحقق من كل IPC input.
- حماية ملف قاعدة البيانات والنسخ الاحتياطية بصلاحيات نظام التشغيل.
- عدم تخزين أسرار تشفير ثابتة داخل ملفات التطبيق.
- تسجيل تدقيق للعمليات الحساسة.

### BACKUP-01: النسخ والاستعادة
- نسخ SQLite بطريقة آمنة تراعي WAL.
- نسخة دورية اختيارية، ونسخة يدوية، ونسخة قبل ترحيل مخطط القاعدة/تحديث التطبيق.
- التحقق من سلامة النسخة وعدد السجلات والمجاميع المالية الأساسية قبل اعتمادها.
- الاستعادة إلى ملف مؤقت ثم فحصه قبل الاستبدال.
- لا تتم الكتابة فوق قاعدة البيانات الحالية قبل نجاح التحقق.
- توفير تصدير إلى مسار خارجي، وعدم الاكتفاء بنسخ احتياطية على نفس القرص.

### BUILD-01: حزمة Windows
- بناء x64 installer بصيغة NSIS EXE.
- تثبيت لكل مستخدم أو لكل الجهاز وفق اختيار واضح.
- قاعدة البيانات في userData مستقلة عن التحديث وإلغاء التثبيت.
- إعداد اسم الناشر والأيقونة والإصدار.
- تثبيت إصدار أحدث فوق القديم لا يزيل مجلد البيانات ولا ينشئ قاعدة جديدة بدل القديمة.
- بناء artifact في Windows runner واختبار تشغيله.

### QA-01: بوابة القبول
- اختبار تثبيت نظيف وتشغيل أول مرة.
- إنشاء مستخدم وتسجيل دخول وصلاحيات.
- إنشاء نشاط وصنف وطرف وصندوق.
- اختبار بيع وشراء وقيد مزدوج وسند وأمانة.
- التحقق من تطابق الأرصدة بعد إغلاق البرنامج وإعادة فتحه.
- إغلاق قسري/إعادة تشغيل أثناء معاملة تجريبية والتحقق من عدم وجود كتابة جزئية.
- إطفاء/إعادة تشغيل Windows ثم التحقق من استمرار السجلات والأرصدة.
- تثبيت إصدار أحدث فوق إصدار سابق والتحقق من بقاء البيانات دون تغيير أو فقد.
- اختبار ترحيل بيانات Dexie ونسخة احتياطية واستعادة.
- اختبار انقطاع الإنترنت؛ العمليات المحلية يجب أن تستمر وفق قواعد النظام.
- اختبار إلغاء التثبيت والتأكد من عدم حذف بيانات المستخدم تلقائيًا.
- لا إصدار إنتاجي قبل نجاح جميع الاختبارات الحرجة.

## شروط عدم الادعاء بالاكتمال

- وجود EXE وحده لا يعني أن SQLite موصولة.
- إنشاء ملف .sqlite وحده لا يعني أن العمليات تستخدمه.
- نجاح Vite build لا يثبت نجاح بناء Windows.
- نجاح CI على Linux لا يغني عن اختبار تثبيت وتشغيل وتحديث على Windows.
- لا تُحذف Dexie أو بيانات المستخدم القديمة قبل نجاح الترحيل والتحقق والنسخ الاحتياطي.
- لا يُعلن أن البيانات محمية من جميع أنواع الفقد؛ يلزم نسخ خارجي لمواجهة تعطل القرص أو فقد الجهاز.

## المخرج النهائي

ملف تثبيت Windows EXE + قاعدة SQLite محلية فعلية + حفظ دائم بعد الإغلاق وإعادة تشغيل الجهاز + ترقية آمنة دون فقد البيانات + أداة نسخ احتياطي واستعادة + تقرير اختبارات Windows + تعليمات تثبيت وتشغيل وترقية.
