# 04 — الاختبارات والإصدار

## لا تفترض أوامر الاختبار

اقرأ package.json وملفات workflow في الفرع الحالي، لأن الأوامر قد تتغير. الأوامر المدرجة حاليًا في إعداد المشروع تتضمن:

- npm run lint
- npm run verify:architecture
- npm test
- npm run test:sqlite
- npm run test:legacy
- npm run verify
- npm run build:windows:preview

شغّل أصغر اختبار مناسب أثناء التعديل، ثم مجموعة التحقق المطلوبة وفق مستوى التغيير. لا تدّعِ نجاح اختبار لم يتم تشغيله.

## تصنيف الأدلة

استخدم هذه المصطلحات بدقة:
- Static review: قراءة وفحص الكود دون تشغيل.
- Unit/integration tests: اختبارات آلية للوظائف والخدمات.
- CI: تنفيذ GitHub Actions على commit محدد.
- Build artifact: ملف تم بناؤه؛ لا يثبت وحده نجاح تثبيته أو تشغيله.
- Windows acceptance: تثبيت وتشغيل واستخدام فعلي على جهاز Windows مستهدف.
- Data migration acceptance: تجربة نقل على نسخة بيانات ممثلة مع مقارنة موثقة.

نجاح CI أو بناء EXE لا يعني وحده أن نسخة Windows جاهزة تجاريًا.

## بوابة القبول لنسخة Windows

- تثبيت نظيف على Windows مستهدف.
- إنشاء المدير الأول وتسجيل الدخول والصلاحيات.
- اختبار إضافة/تعديل منتج وصورة وعميل ومورد.
- اختبار البيع والشراء والمرتجع والقيود والصندوق والسندات والأمانات.
- إغلاق التطبيق وإعادة فتحه ثم إعادة تشغيل Windows والتحقق من بقاء البيانات.
- تحديث إصدار مثبت إلى إصدار أحدث دون فقد البيانات.
- فحص قاعدة البيانات والنسخ الاحتياطي والاستعادة.
- اختبار الطباعة A4 و80mm حسب الأجهزة المتاحة.
- اختبار العمل دون إنترنت وفق الوظائف المعتمدة.
- توثيق إصدار التطبيق وSHA للcommit وسجلات الاختبار.

## بوابة أي تغيير قاعدة بيانات

- لا migrations غير مرقمة أو غير قابلة للتكرار.
- backup قبل migration مع التحقق من قابليته للاستعادة.
- اختبارات نجاح وفشل وترحيل من إصدار سابق.
- مقارنة أعداد السجلات ومجاميع الأرصدة والكميات والدفعات.
- rollback واضح وموثق.
- لا تطبيق على بيانات فعلية قبل موافقة المالك.

## بوابة Pull Request

يجب أن يحتوي PR على:
1. سبب التغيير والنطاق.
2. الملفات المتغيرة.
3. ما لم يتغير صراحة.
4. الاختبارات المنفذة والنتائج.
5. أدلة CI على HEAD الحالي.
6. المخاطر وخطة الرجوع.
7. حالة القبول اليدوي إن كان التغيير يمس Windows أو الطباعة أو التخزين.

لا تدمج PR تلقائيًا. انتظر مراجعة المالك وموافقته الصريحة.
